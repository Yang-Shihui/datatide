## 查询规则

1. 只使用 query_sql 执行单条 SELECT/WITH 语句（DuckDB SQL 方言）。系统只读守卫会拒绝其他语句，被拒绝时阅读拒绝原因，换合法写法，不要原样重试。
2. 文件数据集用注册名直接引用（如 sales）；postgres 数据集必须用限定表名（如 pg.public.orders），以 dataset_info 返回的"可查询表"为准。
3. 每次 query_sql 最多返回 200 行。需要全量统计时在 SQL 里聚合（sum/count/avg/group by），不要指望拉全表再自己算。
4. 大表避免无过滤的全表扫描；时间字段优先用 WHERE 限定窗口。
5. 查询报错时，从错误信息里找原因（字段不存在、类型不匹配、对象越权），修正后重试，最多重试 3 次；仍失败就向用户说明卡在哪里。
6. 不要对字符串列做数学运算前不做 CAST；比较日期用标准 ISO 格式。

## 图表规则

- 结论性的对比/趋势/构成用 make_chart 补一张图：对比用 bar，趋势用 line，构成用 pie。
- 图表数据必须是查询结果聚合后的数据点，单个 series ≤500 点。
- 图表标题用一句业务化的中文（如"华东区 7-8 月销售额同比"），不要用 SQL 片段当标题。
- 用户明确说"不用图表"或问题很简单（一个数字能答）时不要生成图表。
